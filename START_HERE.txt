🔄 KEY WORKFLOW: Appointment Booking

  1. STUDENT BOOKS
     Student → Login page → "Book Appointment"
     Fills: Name, Email, Phone, Date, Time, Reason
     ↓
     API: POST /api/appointments
     ↓
     Appointment created with status: PENDING

  2. STAFF SEES APPOINTMENT
     Staff → Login → Appointments page
     ↓
     API: GET /api/appointments
     ↓
     Lists all pending appointments

  3. STAFF ACCEPTS
     Staff clicks "Accept Appointment"
     Selects blood group (O+, A+, etc)
     ↓
     API: PUT /api/appointments/[id]
     ↓
     Backend AUTOMATICALLY:
       - Updates appointment status to ACCEPTED
       - Extracts student info from appointment
       - Creates new PATIENT with:
         * Name (from appointment)
         * Email (from appointment)
         * Phone (from appointment)
         * Blood group (from selection)

  4. PATIENT AUTO-CREATED
     New patient now visible in Patients page
     Can now receive prescriptions
     Blood group stored for emergencies

  5. STUDENT CHECKS STATUS
     Student → "Check Status" tab
     Enters email → Sees: ACCEPTED
     Shows blood group: O+

💡 IMPORTANT CONCEPTS

1. APPOINTMENT AUTO-CREATES PATIENT
   When staff accepts an appointment, a new patient record is automatically
   created with the student's information. This is the KEY feature.

2. BLOOD GROUP TRACKING
   Blood group is captured during appointment acceptance and stored in the
   patient record for emergency reference.

3. API-FIRST DESIGN
   All features are accessible both via UI and API. You can use the API
   for mobile apps or integrations.

4. STATE MANAGEMENT
   Uses React Context API for global state. All changes to data automatically
   update everywhere in the app.

5. PRODUCTION READY
   The code is production-ready. To deploy, just add a real database
   (PostgreSQL, MongoDB) instead of localStorage.
